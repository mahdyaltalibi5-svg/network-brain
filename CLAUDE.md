# CLAUDE.md — Summit Customs website

The Summit Customs site (summitcustomsuits.com) lives in `summit-customs/`. The CRM lives in `summit-crm/` (see "Summit CRM" below). The site currently live on summitcustomsuits.com (Vercel project `summit-customs-suits`) is the older static build in `summit-suit/`, generated by `python3 summit-suit-src/build.py` (edit the generator, not the HTML; it carries the Meta Pixel 1106836472346765). Its home page film ("The Anatomy of a Suit", chapters I–V ending on the embroidered cuff monogram) is `summit-suit/assets/film.js` + `film.css`; monogram letterforms come from `node summit-suit-src/gen-monogram.mjs`; `?t=<seconds>` pauses the film for screenshots. Smooth scrolling is Lenis (`assets/lenis.min.js`, started in `site.js`). The root `index.html` is an unrelated "Network Brain" page; don't touch it.
Plan: `PLAN.md`. Client-supplied facts still missing: `PLACEHOLDERS.md`.

## Stack
- Next.js App Router + TypeScript. **Every route must be static** (`○`/`●` in the build output, never `ƒ`).
- Tailwind CSS, with all design tokens as CSS variables in `app/globals.css`
- React Three Fiber + drei + @react-three/postprocessing (homepage only, dynamically imported)
- GSAP + ScrollTrigger, Lenis · detect-gpu (benchmarks self-hosted in `public/`)
- Playwright (tests and screenshots) · Lighthouse CI · Deploy: Vercel (Root Directory `summit-customs`)

## Rules
- **Never fabricate business facts.** Use `ph("description")` → renders `[PLACEHOLDER: description]`. Then run `npm run placeholders` to regenerate `PLACEHOLDERS.md`.
- All business facts come from `content/business.ts` (single source for pages, JSON-LD, llms.txt and the sitemap).
- Content first: every page must be complete in the raw HTML without JS (H1, copy, nav, JSON-LD). Exactly one H1 per page.
- Service pages open with a 2–3 sentence answer-first summary.
- No `AggregateRating`/`Review` schema unless `content/reviews.ts` has real reviews.
- 3D is 100% procedural (code-generated geometry, shaders, SVG-sampled points). No .glb models or paid assets.
- 3D never gates content. It needs a reduced-motion/low-tier fallback, an `aria-hidden` canvas and a keyboard-reachable Skip.
- Intro timing lives in **one file**: `summit-customs/three/timeline/ascent.ts`.
- Images: explicit width/height and meaningful alt text.
- Commit after each phase. Run the phase checks first and don't skip a failing check.

## Next.js 16 notes
- Read `summit-customs/node_modules/next/dist/docs/` before using unfamiliar APIs (see `summit-customs/AGENTS.md`).
- Cache Components is on. Static output is enforced by `export const ensureStatic = "navigation"` in `app/layout.tsx`. Don't use `new Date()`, `cookies()` or `headers()` in server components.
- `dynamicParams` isn't available. Unknown journal slugs call `notFound()`.

## Performance rules (Phase 4)
- Fonts are self-hosted subsets in `app/fonts/` with generated per-platform fallbacks (`app/fonts/fallbacks.css`). After copy adds new characters, run `npm run fonts`.
- Inner pages use `content-visibility: auto` below the fold (globals.css). The homepage is excluded because ScrollTrigger needs real geometry.
- Motion libraries load via `whenEngaged()` (`lib/when-engaged.ts`), never on page load.
- Decorative absolutely positioned art must not be bottom-anchored to content-height containers (font swaps would shift it).
- Lighthouse: `npm run lhci` (median of 5). Use `LH_METHOD=devtools node scripts/lh-quick.mjs /path 3` to catch real-network CLS.

## Summit CRM (`summit-crm/`)
- Separate Next.js 16 app (dynamic, password-protected); the website stays fully static. Deploy as its own Vercel project, Root Directory `summit-crm`. Served at summitcustomsuits.com/portal: `basePath: "/portal"` (lib/base.ts; use `withBase()` for hand-built URLs) plus a project-level rewrite on `summit-customs-suits`.
- Meta connection: Settings → "Connect with Facebook" (`lib/meta/connect.ts`, routes `api/meta/connect` + `api/meta/callback`). Saves the app ID/secret and tokens encrypted in `app_settings` (`lib/vault.ts`), subscribes the app webhook + Page to `leadgen`, finds ad account/pixel, polls leads every 5 min via the nudge scheduler. `lib/meta/creds.ts` merges DB values with env vars; never read Meta settings from `config.meta` directly.
- Meta auto-sync: `lib/meta/auto.ts` runs after every CRM page load (`after()` in `app/(crm)/layout.tsx`), from the daily cron and the nudge scheduler; form leads every 4 min, ad account hourly (`lib/meta/ads-sync.ts` mirrors campaigns/adsets/ads + per-ad daily insights into `meta_ads`/`meta_daily`; 90-day backfill on connect). Ads page reads `lib/meta/ads-report.ts`. DMs do NOT become leads (removed; old `dm:` leads are kept, marked lost). Lead forms can live on another of Kobe's Pages ("Kobeapp"): `leadFormIds()` in `lib/meta/leadgen.ts` also reads the form IDs from the ads, and every Page is subscribed to `leadgen`. `/api/meta/diagnose` (signed-in) explains missing leads.
- Meta: Lead Ads webhook `app/api/meta/webhook` (X-Hub-Signature-256 verified) + daily sync `app/api/meta/sync`; Conversions API for CRM in `lib/meta/capi.ts` (system_generated, event_source=crm, lead_id sent as a raw JSON number); ad spend in `lib/meta/insights.ts`.
- Leads are never deleted from the UI: "Mark as lost" (`markLost`, `lost_reason`), reopen by changing stage. Export: `/api/leads/export` (CSV, Pipeline filters). Lists default to newest first.
- Pipeline stages and their Meta event names: `lib/stages.ts`. Don't rename `metaEvent` values once events are flowing.
- DB: `lib/db.ts` uses Postgres when `DATABASE_URL` is set, otherwise PGlite in `.data/` (tests: in memory). Schema in `lib/schema.ts` is idempotent.
- All config via env vars (`.env.example`); never commit tokens. Website leads arrive at `app/api/leads` (CORS: `CRM_ALLOWED_ORIGINS`).
- Speed to lead: `lib/speed.ts` (first_contact_at clock, stats, reminders). Reminders need no outside scheduler: a fresh lead starts `lib/ticker.ts` (POST `/api/speed/tick?key=CRON_SECRET`, runs in `after()` ~4.5 min, ticks every 30 s, re-invokes itself while a fresh lead is uncontacted). `/api/speed/nudge?key=CRON_SECRET` still works for an external scheduler. Today shows "Reply now" (<24 h) apart from older uncontacted leads, alerts `lib/push.ts` (Web Push, VAPID env), Respond screen `app/(crm)/now`. Installable PWA: `app/manifest.ts`, `public/sw.js`.
- Website agent: Website tab → "Ask for a change". `lib/agent/run.ts` (Claude Opus 5.5 tool loop: list/read/search/edit source on GitHub at a pinned commit; edits staged in `agent_files`), `app/api/agent` (NDJSON stream, maxDuration 300), review/publish at `app/(crm)/website/agent/[id]`, `lib/agent/publish.ts` (one commit + Vercel deploy; undo restores originals; refuses if a file changed since). Editable paths only `summit-suit-src/*` and `summit-suit/assets/{site,film}.{css,js}` (`lib/agent/repo.ts`). Keys (Claude, GitHub, Vercel) are pasted in the app and stored encrypted (`lib/secrets.ts`); env vars override.
- Website tab: `lib/site.ts` commits `summit-suit-src/site.json` via the GitHub API and deploys it with the Vercel API (GITHUB_TOKEN, VERCEL_TOKEN). The live-site generator fills `@@TOKENS@@` (phone, email, hours, announcement) from that file; Vercel runs `build.py` on every deploy (`summit-suit/vercel.json`).
- Checks: `npm run check` in `summit-crm/` (lint, types, vitest, build, Playwright; set `PW_CHROMIUM` to the chromium in /opt/pw-browsers).
